# 心理値・StatusSystem

`StatusManager` はランタイム中の6心理値の唯一の正本である。対象は `Affection`、`Sadistic`、`Concern`、`Hostility`、`Obedience`、`Instinct` であり、すべて0から100の独立値として扱う。いずれかの値の変更によって、他の値を自動変更しない。

- `Affection`: プレイヤーへの愛着・愛おしさを表す長期的な関係値。
- `Sadistic`: プレイヤーを支配・からかう・いじめたい欲求。嫌悪とは独立し、Affectionと同時に高くなり得る。
- `Concern`: プレイヤーの安全への心配・保護欲。比較的変動しやすい。
- `Hostility`: プレイヤーへの怒り・対立・敵対姿勢。Affectionの反対値ではない。
- `Obedience`: プレイヤーを主人として扱い、要求や命令に従いたい傾向。Affectionや信頼とは独立する。
- `Instinct`: 理性的な判断より猫としての本能・衝動が前面に出る度合い。捕食・遊び・狩猟を含む。

`CatDataSO` はキャラクター固定設定と心理値の初期値・基準値を保持する。ゲーム開始時に `StatusManager` が読み取り、その後の値をアセットへ書き戻してはならない。

変更は会話、行動、イベント、Yarn、デバッグUIから `StatusManager.SetValue` または `ApplyEffects` を通して行う。変更時には `StatusChangeResult` に種類、変更前後、差分、Reason、SourceIdを記録し、`ConversationGameState` とYarnへ投影する。`ConversationGameState` は会話条件評価用の投影データであり、心理値の正本ではない。

会話CSVでは、心理値別の分岐を `condition` 列で制御する。`StatusManager` は各数値に加えて、代表心理状態を `PsychologyState` と `psychology_state` へ投影する。値は `NORMAL`、単一状態の `HOSTILITY`、または値が高い上位2状態をアルファベット順で連結した `AFFECTION_HOSTILITY` の形式となる。例えば `condition` には `PsychologyState == "HOSTILITY"`、または `PsychologyState == "AFFECTION_HOSTILITY"` を指定する。

70以上の値をActiveとする。Activeがなければ代表心理Stateは`Normal`、1つならその種類、複数なら数値が高い上位2つを代表Stateにする。同値は直近に上昇した値を優先し、未変更同士は `StatusType` の固定順を使う。最大値100の判定はイベント条件として利用可能だが、既読フラグは別のゲームStateで管理する。

## 通常会話5回の結果（Issue #43）

既存`DialogueManager`が、Engineから受け取った通常会話の終了時に1回を数える。複数ページでも1回。5回目で既存`SystemTimedEvent.csv`の`PRD_CONVERSATION_RESULT_NORMAL`、または`AFFECTION / CONCERN / HOSTILITY / INSTINCT / SADISTIC / OBEDIENCE`を末尾に持つ結果を表示する。新しい台詞やRuntimeマネージャーは追加しない。

対象はNormal/Reactionの通常グループ。聞き直し、直接Pattern再生、挨拶、教示、Call/Return、Choice、Action/Event、Timeline指定、内部会話、結果会話は加算しない。特殊会話・時間経過・タイトル再開始では区間をリセットする。聞き直しは区間を維持する。

心理値はこの区間の通常会話完了時に`ApplyDelta`で実際に変更された種類を保持する。現在高いだけの値、上限/下限で変化しなかった操作は対象外。減少や増減が相殺された場合も、途中の実際の変化として保持する。複数種類では`StatusManager.GetHighestPriorityStatus`から既存代表心理と同じ順位（現在値、最終上昇順、固定順）で1種類を選ぶ。70未満でも実際に変化していれば候補とする。

暗転後に既存結果UIへ結果を表示し、表示完了後に既存の時間経過・明転・時間帯挨拶/夜日記へ進む。結果CSVの`time_minutes`が空欄の現状では、既存時間経過フローの120分を使う。表示時間はCSV指定、空欄は既存2.8秒。5回区間は時間進行時に0へ戻る。通常のAction/Eventは従来どおりの表示・時間進行順を維持する。結果待機中のタイトル復帰/破棄では継続をキャンセルし、旧処理による追加時間進行を防ぐ。

回帰は`DialogueConversationIntervalTests.cs`で通常/6心理値、変化なし、上限、減少/相殺、複数心理順位、リセット、対象除外、実配布用CSVの通常会話判定を検証する。

## 2026-10-12改修（Issue #70）

初期値と日付経過で戻る基準値は同じ`CatDataSO`の6項目を使う。配布設定`NewNekomataData`は愛情50・ドS30・心配30・敵対0・従順30・本能0。範囲0〜100、各値は独立。設定アセットの変更は基準値へ反映し、保存済み実測値を初期値で上書きしない。

日付更新は既存`TimeManager`の通知直前に`StatusManager.ProcessDateUpdate`へ接続する。心理ごとの最後の実上昇日を保存し、上昇日と翌日は保持、2日後から1日につき最大10だけ基準値へ戻る。基準値未満は増加、超過は減少、基準値を跨がない。下降・変化0・自然回復は上昇日/上昇順を更新しない。愛情90が1日目に上昇した例は2日目90、3日目80、4日目70、5日目60、6日目50。複数日をまとめて進めても各日を処理し、処理済み日付以下の通知/再読込/デバッグ巻き戻しで二重適用しない。

代表心理の活性閾値70と上位2種類は維持。主/副は値降順、同値は最後の上昇順、それも同じならStatusType固定順。会話用キーは従来どおり英名をアルファベット順に連結する。条件評価でも複合の順序を正規化し、旧逆順キーを受け付ける。従順100の特例・モーション/表情接続は追加しない。

### 保存・移行

既存`ProgressSaveStore`の`Nekolpos.Status.State.v1`へ6値・各最終上昇日/順・最終処理日を一つのJSONとして保存。値変更/日付処理完了後に保存し、起動時は保存値優先。EditorのEditModeでは自動読込/自動保存を行わずテスト用操作のみ、Play/Playerは既存の進行保存バックエンド（Editor/WebGLはPlayerPrefs、通常Playerはprogress-v1.json）を利用。PlayerPrefsから正式ファイルへの旧進行移行にも新キーを追加。

従来コードに心理値・上昇日の永続化はなかった。専用心理保存がない旧進行では設定初期値から開始し、最終上昇日/処理日を読み込み当日にして過去日を遡って減衰させない。値のみのv1保存なら実測値を維持し欠落日付を当日、順を0に補完。不正/未知版/欠損値の保存はエラーにして上書きしない。明示的新規ゲーム用`ResetForNewGame`は心理保存のみ削除して設定初期値へ戻す（通常の読込では呼ばない）。新たなタイトル/セーブスロットUIは追加しない。

## 命令口調の自動加算（Issue #72）

成立した自由入力について、`CommandToneDetector` が命令口調を検知すると `StatusManager.ApplyDelta(Obedience, 10, "CommandTone", "FreeInput.CommandTone:<送信固有ID>")` を適用する。1送信最大+10、同文の新しい送信は毎回加算、上限100。他心理値は変更しない。専用会話の効果とは別枠で、`命令を聞いて` は専用+10のみ、`命令を聞け` は専用+10と自動+10。

ルール正本は `Assets/Scripts/System/CommandToneInput.cs`。原文をFormKC化した判定用コピーを使用し、句読点・空白・改行で節を区切る。通常Regex用原文・読み正規化は変更しない。以下の限定辞書を使用する（ひらがな表記もコード記載の範囲で対応）。

- 命令語: 待て、来い、行け、黙れ、やめろ、止めろ、しろ、せよ、やれ、いろ、居ろ、聞け、見ろ、座れ、立て、出ろ、寝ろ。
- 禁止: 触る、動く、行く、来る、話す、喋る、見る、する、近づく＋「な」。
- なさい: 片付け、待ち、来、行き、聞き、座り、寝、見、やめ、し＋「なさい」。
- 事前指示: 見て、聞いて、覚えて、待って＋「おけ／おいてくれ」。
- 要求: 持ってきて、持って来て、手伝って、待って、来て、見て、聞いて、やって、助けて、片付けて＋「くれ」。
- 許可する前置き: そこ／ここ／あそこ／こっち／そっち／あっち＋に／へ／で、今すぐ、すぐ、早く、はやく、ちゃんと、命令／話／言うこと／いうこと＋を。末尾のよ／ね／ぞを許可。
- 除外: 引用符・括弧内、未閉じ引用、と言／とい／って言／ってい／という／っていう、命令形、命令口調、例文、言葉／ことば、台詞／せりふ／セリフを含む説明。丁寧依頼、単なる「て」、帰ろ、面白いだろ等は辞書非該当。

保守的な限定辞書のため、未知動詞や長い説明付き指示は検出しない場合がある。一般的な「ろ／れ／てくれ」末尾一致や外部AI通信は使用しない。

`ChatUIController` の既存送信抑止・入力確定・猫応答待機の後、`DialogueEngine.ProcessSubmittedFreeInput` で送信ごとの `CommandToneInput` を作る。Managerが反応を受付した時点で一度だけ消費し、通常会話は再生開始時、UnknownWordは学習開始時に適用。夜／時間進行中などManagerが受付しない入力、応答決定失敗、待機中キャンセルは適用しない。直接ProcessInput、教示再評価、選択肢、ログ、直接Pattern再生には送信情報を新設しない。通常会話のマッチングは加算前に完了する。

通常会話は再生開始時の `pendingNormalConversation` 設定後に実差分を区間候補へ記録し、#43の従順結果に反映する。特殊会話は既存の区間リセットに従う。変更履歴、代表心理、日付減衰、保存はStatusManagerの既存APIに従う。
